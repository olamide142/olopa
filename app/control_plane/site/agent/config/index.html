Configuration

Agent Configuration

Runtime IR, ingest endpoint, tenant identity, auth, probe events, and enforcement configuration for the olopa agent.

Core config

Env varCLI flagDefaultDescription
OLOPA_RUNTIME_IR --runtime-ir /etc/olopa/runtime-ir.json Path to the oilc-emitted runtime IR artifact loaded at startup
OLOPA_INGEST_URL --ingest-url http://ingest.olopa.io/api/v1/ingest/batches HTTP endpoint for ingest batch POSTs
OLOPA_INGEST_TENANT_ID --ingest-tenant-id default Tenant ID included in outgoing ingest payloads
OLOPA_INGEST_HOST_ID / HOSTNAME --ingest-host-id agent-local (or hostname) Host identity included in ingest payloads
OLOPA_IFACE --iface — Network interface for BPF attach helpers (e.g. eth0, lo)
OLOPA_STATUS_PATH --status-path /tmp/olopa/agent/status.json Location of runtime status snapshot used by olopa status
OLOPA_AGENT_ID — 1 Numeric agent ID used in ingest payloads to distinguish multiple agents on one host

Auth options

Env var / FlagHeader sent to ingestNotes
OLOPA_INGEST_API_TOKEN / --ingest-api-token Authorization: Bearer <token> Preferred option when ingest is configured with API tokens
OLOPA_INGEST_API_KEY / --ingest-api-key x-api-key: <key> Alternative auth header supported by ingest server

Probe events

Controls which kernel-level event sources the agent attaches to. Set via OLOPA_PROBE_EVENTS (comma-separated) or --probe-events.

ProbeEvents capturedOIL sourceActive by default
fork Process fork events endpoint.process Yes
exec Process exec events endpoint.process Yes
file File open / write events endpoint.file Yes
net Network connection events network.flow Yes
xdp XDP-layer packet events (lower-level) — No
tc TC firewall — enforces block egress OIL actions respond block egress No
sql Activates the SQL policy socket that PQexec/mysql_real_query guards call into db.query No
ssl TLS payload visibility via EVP_EncryptUpdate/EVP_DecryptUpdate uprobes — No
dns getaddrinfo resolution events — No
Note: The default probe set is fork,exec,file,net. Enable additional probes as needed — for example, add tc to enforce block egress rules from OIL, or sql to turn on client-library SQL enforcement (see SQL enforcement below). 
# Enable all probes including TC enforcement
OLOPA_PROBE_EVENTS=fork,exec,file,net,tc cargo run ... -- --iface eth0

# Or via CLI flag
cargo run ... -- --iface eth0 --probe-events fork,exec,file,net,tc

TC enforcement

The tc probe implements network-level enforcement for OIL block egress actions. Deny rules are injected as TC classifier entries.

Env varFormatDescription
OLOPA_TC_DENY_RULES pid=X,ip=Y,port=Z,proto=tcp|udp Comma-separated TC deny policy entries. All fields are optional — omitted fields match any value. 
# Block process 1234 from reaching 10.0.0.1:443 over TCP
export OLOPA_TC_DENY_RULES="pid=1234,ip=10.0.0.1,port=443,proto=tcp"

# Multiple rules (semicolon-separated)
export OLOPA_TC_DENY_RULES="pid=1234,ip=10.0.0.1,port=443,proto=tcp;ip=192.168.1.0,port=80"
Requires: The tc probe must be active (--probe-events tc or OLOPA_PROBE_EVENTS=...,tc) and the agent must be running with sufficient kernel privileges for TC attachment.

SQL enforcement

The olopa-sql-guard preload library intercepts PostgreSQL (PQexec, PQexecParams, PQsendQuery, PQsendQueryParams, PQexecPrepared, PQsendQueryPrepared) and MySQL (mysql_query, mysql_real_query, mysql_stmt_execute) client calls at the library boundary and sends a bounded, redacted request to a Unix socket the agent listens on. The agent evaluates the same runtime OIL program used for kernel events and returns an allow or block verdict before the real driver function runs — the query never reaches the database when blocked. Raw statement text is never logged or persisted.

Env varDefaultDescription
OLOPA_SQL_POLICY_ENABLED disabled Set truthy to start the SQL policy socket
OLOPA_SQL_POLICY_MODE observe observe records telemetry only; enforce blocks denied statements
OLOPA_SQL_POLICY_SOCKET /run/olopa/sql-policy.sock Unix socket path guarded processes connect to
OLOPA_SQL_POLICY_TIMEOUT_MS 250 Per-request evaluation timeout
OLOPA_SQL_POLICY_WORKERS 4 Worker threads servicing the socket (clamped 1–64)
OLOPA_SQL_POLICY_QUEUE_CAPACITY 256 Pending-request queue depth (clamped to workers–65536)
OLOPA_SQL_POLICY_GID — Group ownership applied to the socket (0660) so a non-root DB process can connect 
# Build the guard and preload it into a guarded process
cargo build --manifest-path agent/Cargo.toml -p olopa-sql-guard

export OLOPA_SQL_POLICY_ENABLED=1
export OLOPA_SQL_POLICY_MODE=observe   # flip to enforce once verdicts look right
LD_PRELOAD=agent/target/debug/libolopa_sql_guard.so your-app
Tip: Start in observe mode and confirm verdicts against real traffic before switching to enforce — see Quickstart for the full compile → run → verify loop.

Graph dump

The agent can periodically write a JSON snapshot of the observed process/network graph for debugging and inspection.

FlagDefaultDescription
--graph-dump-path <path> /tmp/olopa_graph.json Output file for the graph JSON snapshot
--graph-dump-interval-ms <ms> 1000 Minimum interval between graph dump writes (rate limit)
--no-graph-dump — Disable graph JSON dumps entirely

Recommended environment block

export OLOPA_RUNTIME_IR=/etc/olopa/runtime-ir.json
export OLOPA_INGEST_URL=http://127.0.0.1:8000/api/v1/ingest/batches
export OLOPA_INGEST_TENANT_ID=acme
export OLOPA_INGEST_HOST_ID=host-01
export OLOPA_INGEST_API_TOKEN=agent-acme-token
export OLOPA_STATUS_PATH=/tmp/olopa/agent/status.json
export OLOPA_PROBE_EVENTS=fork,exec,file,net

CLI override example

cargo run --manifest-path agent/Cargo.toml -p olopa -- \
  --iface eth0 \
  --runtime-ir /etc/olopa/runtime-ir.json \
  --ingest-url http://127.0.0.1:8000/api/v1/ingest/batches \
  --ingest-tenant-id acme \
  --ingest-host-id host-01 \
  --ingest-api-token agent-acme-token \
  --probe-events fork,exec,file,net,tc
Tip: Pass --print-effective-config to print the resolved startup configuration and exit without running — useful for verifying env vars are applied correctly.

Status command

The status subcommand reads the runtime status snapshot and displays agent health, active probes, and ingest stats.

# Basic status
cargo run --manifest-path agent/Cargo.toml -p olopa -- status

# Verbose output with full event counters
cargo run --manifest-path agent/Cargo.toml -p olopa -- status --verbose

# Machine-readable (no color, no mascot)
cargo run --manifest-path agent/Cargo.toml -p olopa -- status --no-color --no-mascot

Fallback behavior

If runtime IR fails to load, agent startup fails by default. Enable the simple-rule fallback only for temporary recovery scenarios — it provides minimal detection capability without the full OIL rule set.

# Via environment variable
export OLOPA_ALLOW_SIMPLE_RULE_FALLBACK=1

# Via CLI flag
cargo run ... -- --allow-simple-rule-fallback
Warning: The fallback matcher does not evaluate OIL rules. Use this only as a last resort while recovering a broken IR artifact — not in production.
