Language Reference

OIL

The Olopa Intent Language — a declarative, event-driven detection language for writing security rules that correlate streams, score risk, emit facts, and trigger responses.

Introduction

OIL rules describe what to look for across live event streams — processes, network flows, file events, container activity, DNS queries, and more. Rules are compiled by oilc to a runtime IR artifact that the olopa agent loads and evaluates continuously against kernel-level telemetry.

A rule declares which event sources it cares about (from), how events join together (correlate), the conditions that trigger it (where), an optional risk score (score), side-effects (emit / respond), and an optional gate (require). All other constructs — set, predicate, callable, fact, entity, root — are the vocabulary that rules draw from.

Declarative

Describe detections at the semantic level. The runtime handles joining, windowing, and evaluation.

Composable

Share reusable predicates, callable lookups, and named facts across many rules.

Risk-aware

Inline score blocks accumulate evidence and gate response severity dynamically.

Stateful

emit fact publishes named state that other rules can consume within a TTL.

File Structure

An OIL file is a sequence of top-level declarations in any order. use imports bring external callables or sets into scope.

// Optional: import external symbols
use intel.malicious_domains
use baseline.workload_profiles

// Named constant sets
set shells = ["bash", "sh", "zsh"]

// Reusable predicate
predicate is_shell(p) =
  p.name in shells

// Fact template
fact host.root_ssh_write(host_id) expires 6h

// Detection rule
rule "my_detection" {
  // ... clauses ...
}
Tip: Built-in sets, predicates, and callables from the stdlib are available globally — no use needed.

OIL source is compiled by oilc into a runtime IR artifact (JSON), which the olopa agent loads at startup. The agent evaluates the IR continuously against live kernel telemetry.

Duration literals

Duration values are suffixed with a time unit: 30s, 5m, 2h, 24h. Used in within, around, expires, and callable arguments.

Sets

Named, typed collections of literals. Sets are referenced in in / not_in expressions and passed to predicates or callables.

set c2_ports      = [4444, 1337, 31337, 9001]
set credential_paths = [
    "/etc/shadow", "/etc/passwd", "/etc/sudoers",
    "~/.aws/credentials", "~/.ssh/id_rsa"
]

Inline arrays work directly in where expressions too:

where
  p.name in ["bash", "sh", "zsh"]
  and f.path matches ["/etc/shadow", "~/.aws/credentials"]
Tip: Use matches for glob-style path matching (e.g. "/home/*/.ssh/id_rsa"). Use in for exact set membership.

Entities & Roots

Entities are named field schemas. Roots are globally available, pre-declared bindings to entity instances that rules can reference directly.

// Defining a custom entity
entity TimeContext {
    weekday: Str,
    hour:    Int,
    minute:  Int,
    is_business_hour: Bool,
}

// Declaring a root binding
root time: TimeContext

These are available without declaration in any rule:

Predicates

Predicates are named boolean functions over one or more arguments. They are evaluated inline wherever they are called — there is no separate invocation overhead.

predicate is_shell(p) =
  p.name in shells

predicate unusual_country(user, country) =
  country not_in user.baseline.countries

predicate external_c2(endpoint) =
  endpoint.is_internal == false
  and (endpoint.port in c2_ports or endpoint.reputation in malicious_reputation)

Predicates can call other predicates and reference any in-scope set or callable. They are used in where expressions, let bindings, and other predicates.

// Calling a predicate inside another
predicate unsigned_from_tmp(proc) =
  from_tmp(proc) and proc.signed == false

Callables

Callables declare external functions resolved by the runtime engine — they are not defined inline. They may return scalar values, Booleans, or structured types like BaselineProfile or Set<Str>.

// Declare the signature (in builtins or a module)
callable baseline.workload(namespace: Str, name: Str) -> BaselineProfile
callable intel.domains(feed: Str) -> Set<Str>
callable rare(value: Str) -> Bool
callable rate(value: Str, window: Duration) -> Int

// Using a callable in a rule's where clause
where
  p.name not_in baseline.workload(w.namespace, w.name).allowed_processes
  and rate(n.dest.domain, 1m) >= 8

Facts

Facts are named, parameterized state with a TTL. A fact template is declared at the top level; rules emit and consume instances. Other rules can reference emitted facts in their where clause.

// Declare a fact template with a default TTL
fact host.root_ssh_write(host_id) expires 6h
fact host.binary_tamper(host_id)  expires 24h
fact container.high_risk(container_id) expires 24h

// Emit a fact instance inside a rule
emit
  fact host.root_ssh_write(host.id) expires 6h
Note: Facts enable chained detections — rule A emits a fact that lowers the score threshold in rule B, allowing multi-stage attack sequences to trigger higher-severity responses.

Rule Anatomy

A rule is a named block containing ordered clauses. Only from, correlate, where, and respond are required for a minimal rule — the rest are optional enrichments.

rule "rule_name" {
  from      // event sources to subscribe to
  correlate // join event streams on shared keys
  where     // boolean filter predicate
  within    // optional time window for correlation
  let       // named boolean/value bindings
  score     // base score + conditional adjustments
  require   // gate: rule only fires if condition met
  emit      // publish facts for other rules
  respond   // actions: alert, block, snapshot, etc.
}

from

Declares which telemetry sources the rule subscribes to. Use dot-notation: source.stream. The agent must have the corresponding probe enabled for the source to receive events.

from endpoint.process, network.flow
from endpoint.file, endpoint.process
from container.runtime, k8s.admission, identity.session
from endpoint.process, network.flow, container.runtime, k8s.workload
SourceEventsAgent probe
endpoint.processProcess spawn eventsfork, exec
endpoint.fileFile open/write eventsfile
network.flowNetwork connection eventsnet
container.runtimeContainer start/stop eventsfork + namespace tracking
k8s.workloadKubernetes workload metadatak8s informer
k8s.admissionKubernetes admission eventsk8s webhook
identity.sessionAuth session eventsPAM / session hooks
Tip: The agent's active probes are controlled by OLOPA_PROBE_EVENTS (or --probe-events). Default active probes: fork,exec,file,net. The tc probe must be explicitly enabled for block egress enforcement.

correlate

Joins event streams into a single match context. Events are bound to aliases using as and joined to previous bindings using on conditions or by shortcuts.

correlate
  process.spawn as p
  with file.open   as f  on f.process_id == p.id
  with network.connect as n  on n.process_id == p.id

The by shorthand links a file or network event directly to the spawning process:

// "file.write by process" is sugar for joining on process_id
correlate
  file.write as f by process as p
Tip: Aliases declared in correlate are available throughout the rest of the rule — in where, let, score, emit, and respond.

where

The boolean filter that must evaluate to true for a rule to trigger. All conditions are joined with and / or.

where
  p.name in ["bash", "sh", "zsh"]
  and f.path matches ["/etc/shadow", "~/.aws/credentials"]
  and n.dest.domain in malicious_domains
  and n.direction == "outbound"
  and n.dest.domain != null

Path membership: under

under tests whether a path is a descendant of any path in a set — equivalent to a prefix match.

where
  f.path under "/root/.ssh"

// Or against a set of prefixes
where
  f.path under executable_dirs

let

Computes named boolean or value bindings for use in score conditions and respond blocks. Bindings make complex conditions readable and reusable within a rule.

let
  prod           = w.namespace in ["prod", "payments", "identity"]
  interactive    = p.tty == true
  rare_process   = p.name not_in baseline.workload(w.namespace, w.name).allowed_processes
  unusual_dest   = n.dest.domain not_in host(p.host_id).baseline.domains
  burst          = rate(n.dest.domain, 30s) >= 4
  large_egress   = n.bytes_out > 250000

score

Accumulates a numeric risk score. Starts from a base value and applies conditional adjustments. The result is available in respond as score.

score
  60
  +20 if rare_for_workload
  +10 if prod
  +10 if suspicious_dest
  -30 if package_mgmt
  +15 if interactive
  +20 if suspicious_path

Adjustments can be positive (raise confidence) or negative (lower it). The score feeds directly into conditional branching in respond and can gate rule firing via require score >= N.

emit

Publishes a named fact instance to the shared fact store. Other rules within the TTL window can reference this fact in their where or score clauses.

emit
  fact host.compromise_candidate(host.id) expires 24h

emit
  fact host.binary_tamper(host.id) expires 24h

respond

Specifies actions when the rule matches. Supports unconditional actions and if score >= N branches for severity tiering.

// Simple unconditional response
respond
  alert critical
  block egress n.dest.domain
  snapshot p, n
  open case "Blocked outbound to protected website"

// Score-gated branching
respond
  if score >= 90 {
    alert critical
    isolate host
    snapshot p, f, n, c, w
    open case "Container credential access and egress chain"
  } else {
    alert high
    snapshot p, f, n
  }

Response actions

ActionDescriptionRequires
alert <severity>Emit an alert at the given severity (low / medium / high / critical), with an optional message string—
block egress <target>Block outbound traffic to the specified domain or IP via TC firewall rulestc probe active
isolate hostNetwork-isolate the host where the event occurredagent privileges
snapshot <aliases…>Capture a forensic snapshot of the listed correlated events—
open case <title>Open a named investigation case—
Note: block egress enforcement is backed by the agent's TC (traffic control) firewall hook. Ensure the agent is started with tc in OLOPA_PROBE_EVENTS (or --probe-events tc) and that OLOPA_TC_DENY_RULES is configured. Without the tc probe the action is logged but not enforced.

require

A final gate — if the condition is false the rule does not fire, regardless of where. Typically used to enforce a minimum score threshold.

require
  score >= 40
Tip: require is evaluated after score is computed, so negative adjustments (e.g. -30 if package_mgmt) can suppress a rule entirely for known-good processes.

within

Constrains correlated events to a sliding time window. All events in the correlate block must occur within the duration of the anchor event.

within 15m

Place within after the where block. If omitted, correlation is unbounded (or uses the runtime default).

around

around is a temporal grouping primitive. It aggregates multiple event types on a shared key within a time window, without requiring strict join conditions between individual events.

around host.id within 10m {
  process.spawn as p,
  network.connect as n
}

where
  p.name in ["sh", "bash", "zsh"]
  and n.direction == "outbound"

respond
  alert high "Interactive shell with outbound activity in host window"

Useful for hunting patterns where you care about co-occurrence on an entity (host, user, pod) rather than strict causal joins.

graph

graph matches structural event topology — the shape of relationships between event types — rather than individual event attributes. Useful for lateral movement and attack-chain detection.

graph endpoint.process as e {
  process as p,
  network as n -> connects_to
}

where
  e.pid > 0
  and n.dest.port in [22, 3389, 445]
  and rate(n.dest.domain, 5m) >= 6

respond
  alert medium "Graph lateral movement shape candidate"

Edge labels like connects_to describe the relationship semantics. The runtime evaluates whether the observed event graph matches the declared topology.

Rule Gallery

Outbound to specific domain

rule "outbound_to_specific_website" {
  from endpoint.process, network.flow

  correlate
    process.spawn as p
    with network.connect as n on n.process_id == p.id

  where
    n.direction == "outbound"
    and n.dest.domain in ["apple.com"]

  respond
    alert critical
    block egress n.dest.domain
    snapshot p, n
    open case "Blocked outbound to protected website"
}

Business-hours variant with time context

rule "outbound_to_specific_website_business_hours" {
  from endpoint.process, network.flow

  correlate
    process.spawn as p
    with network.connect as n on n.process_id == p.id

  where
    n.direction == "outbound"
    and n.dest.domain in ["apple.com"]
    and time.weekday == "saturday"
    and time.hour >= 9
    and time.hour < 23

  respond
    alert critical
    block egress n.dest.domain
    snapshot p, n
    open case "Blocked outbound during business hours"
}

Scored rule with require gate

set executable_dirs = ["/bin", "/sbin", "/usr/bin", "/usr/local/bin"]

rule "binary_directory_modification" {
  from endpoint.file, endpoint.process

  correlate
    file.write as f by process as p

  where
    f.path under executable_dirs

  let
    package_mgmt    = p.name in ["apt", "apt-get", "dpkg", "yum"]
    interactive     = p.parent.name in ["bash", "sh", "zsh"]
    suspicious_path = p.binary.path under ["/tmp", "/var/tmp", "/dev/shm"]

  score
    60
    -30 if package_mgmt
    +15 if interactive
    +20 if suspicious_path
    +10 if p.user.name != "root"

  require
    score >= 40

  emit
    fact host.binary_tamper(host.id) expires 24h

  respond
    if score >= 80 {
      alert critical
      snapshot p, f
      open case "Executable directory modification"
    } else {
      alert medium
    }
}

Full multi-stream correlated detection

use intel.malicious_domains
use baseline.workload_profiles

rule "container_shell_credential_access_and_egress" {
  from endpoint.process, endpoint.file, network.flow,
       container.runtime, k8s.workload

  correlate
    process.spawn     as p
    with file.open    as f on f.process_id == p.id
    with network.connect as n on n.process_id == p.id
    with container.context as c on c.container_id == p.container_id
    with workload.info as w on w.pod_uid == c.pod_uid

  where
    p.name in ["bash", "sh", "zsh"]
    and f.path matches ["/etc/shadow", "/root/.ssh/id_rsa", "~/.aws/credentials"]
    and n.dest.domain in malicious_domains

  within 15m

  let
    prod         = w.namespace in ["prod", "payments", "identity"]
    interactive  = p.tty == true
    rare_process = p.name not_in baseline.workload(w.namespace, w.name).allowed_processes
    unusual_dest = n.dest.domain not_in host(p.host_id).baseline.domains

  score
    70
    +10 if prod
    +10 if interactive
    +10 if rare_process
    +10 if unusual_dest

  emit
    fact host.compromise_candidate(host.id) expires 24h

  respond
    if score >= 90 {
      alert critical
      isolate host
      snapshot p, f, n, c, w
      open case "Container credential access and egress chain"
    } else {
      alert high
      snapshot p, f, n
    }
}
